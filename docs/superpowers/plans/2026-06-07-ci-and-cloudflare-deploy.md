# CI + Cloudflare Deploy (beta.do.zone) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add GitHub Actions CI that builds + tests `thedozone2` on every push/PR, and auto-deploys the static SPA to `beta.do.zone` (Cloudflare Worker + static assets, via Wrangler) on every push to `main`.

**Architecture:** A single workflow with two jobs. The `build` job checks out the sibling `reubenfirmin/zoned` repo, publishes its private `1.0-SNAPSHOT` artifacts to Maven Local using zoned's own bootstrap pattern, then builds + tests `thedozone2` and uploads the assembled site (`build/dist/js/productionExecutable`) as an artifact. The `deploy` job (only on `main`) downloads that artifact and runs `npx wrangler deploy`, which ships the static assets to a Cloudflare Worker bound to `beta.do.zone`.

**Tech Stack:** Kotlin Multiplatform (JS/IR browser target), Gradle, GitHub Actions, Cloudflare Workers Static Assets, Wrangler CLI, Node.

Notes for the implementer (zero-context assumptions):

- The deployable site is produced by Gradle task **`jsBrowserDistribution`** into `build/dist/js/productionExecutable/`. Do **not** use `jsBrowserProductionWebpack` alone — it omits HTML/CSS/icons.
- Tailwind CSS is generated by the Zoned Gradle plugin task **`build-style`**, which writes `src/jsMain/resources/style.css`. Run it before/with the distribution.
- The build requires private artifacts (`io.4rc.zoned.plugin`, `io.4rc:zoned-js`, etc., all `1.0-SNAPSHOT`) that exist only in `~/.m2`, produced by the `reubenfirmin/zoned` repo. CI builds them itself.
- This is infra/config work, so "tests" are **validation commands** (dry-runs, YAML lint, real CI run) rather than unit tests. Each task ends with a concrete verification + commit.

## Task 2: Add the CI `build` job (build + test + upload artifact)

**Files:**
- Create: `.github/workflows/ci.yml`

- [ ] **Step 1: Create `.github/workflows/ci.yml` with the `build` job**

```yaml
name: CI

on:
  push:
    branches: ["**"]
  pull_request:
  workflow_dispatch:

permissions:
  contents: read

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

env:
  # Ref of reubenfirmin/zoned to build the private 1.0-SNAPSHOT artifacts from.
  # Pin to a commit SHA here if master drift ever breaks the build.
  ZONED_REF: master

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout thedozone2
        uses: actions/checkout@v4
        with:
          path: thedozone2

      - name: Checkout zoned
        uses: actions/checkout@v4
        with:
          repository: reubenfirmin/zoned
          ref: ${{ env.ZONED_REF }}
          path: zoned

      - name: Set up JDK 21
        uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '21'

      - name: Set up Gradle
        uses: gradle/actions/setup-gradle@v4

      - name: Set up Chrome (for Karma headless tests)
        uses: browser-actions/setup-chrome@v1
        id: setup-chrome

      - name: Export CHROME_BIN
        run: echo "CHROME_BIN=${{ steps.setup-chrome.outputs.chrome-path }}" >> "$GITHUB_ENV"

      # zoned's root build applies its own Gradle plugin, so it can't configure
      # until that plugin exists in a repo. Bootstrap by publishing :gradle-plugin
      # with self-application temporarily disabled, restore, then publish the rest.
      - name: Publish zoned artifacts to Maven Local
        working-directory: zoned
        run: |
          chmod +x ./gradlew
          sed -i 's#id("io.4rc.zoned.plugin")#// id("io.4rc.zoned.plugin")#' build.gradle.kts
          ./gradlew --no-daemon :gradle-plugin:publishToMavenLocal
          git checkout -- build.gradle.kts
          ./gradlew --no-daemon publishToMavenLocal

      - name: Build, test, and assemble site
        working-directory: thedozone2
        run: |
          chmod +x ./gradlew
          ./gradlew --no-daemon build-style build jsBrowserDistribution

      - name: Upload site artifact
        uses: actions/upload-artifact@v4
        with:
          name: site
          path: thedozone2/build/dist/js/productionExecutable
          if-no-files-found: error

      - name: Upload test results
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: test-results
          path: |
            thedozone2/build/test-results/**/*.xml
            thedozone2/build/reports/tests/**
          if-no-files-found: ignore
          retention-days: 7
```

Note: because `thedozone2` is checked out into a `thedozone2/` subdir (so `zoned` can sit beside it at `zoned/`), `wrangler.jsonc`'s relative `directory` resolves the same way in the deploy job (see Task 3).

## Task 3: Add the CI `deploy` job (wrangler deploy to beta)

**Files:**
- Modify: `.github/workflows/ci.yml`

- [ ] **Step 1: Append the `deploy` job to `.github/workflows/ci.yml`**

Add this job under `jobs:` (sibling of `build:`):

```yaml
  deploy:
    needs: build
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main' && github.event_name != 'pull_request'
    permissions:
      contents: read
    steps:
      - name: Checkout thedozone2 (for wrangler.jsonc)
        uses: actions/checkout@v4

      - name: Download site artifact
        uses: actions/download-artifact@v4
        with:
          name: site
          path: build/dist/js/productionExecutable

      - name: Set up Node
        uses: actions/setup-node@v4
        with:
          node-version: '22'

      - name: Deploy to beta.do.zone
        run: npx --yes wrangler@latest deploy
        env:
          CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
```

Note: the deploy job checks out the repo at its root (so `wrangler.jsonc` is at the working dir root) and downloads the artifact into `build/dist/js/productionExecutable`, matching the `directory` path in `wrangler.jsonc`. This differs from the `build` job's `thedozone2/` subdir layout but is internally consistent because the deploy job does a plain root checkout.

## CI / Deploy

CI is GitHub Actions (`.github/workflows/ci.yml`):

- **build** (every push + PR): checks out `reubenfirmin/zoned`, publishes its
  `1.0-SNAPSHOT` artifacts to Maven Local, then builds + tests this repo and
  uploads the assembled site.
- **deploy** (push to `main` only): runs `wrangler deploy`, shipping the static
  site to a Cloudflare Worker bound to **beta.do.zone**.

### One-time manual setup (repo owner)

1. **`do.zone` must be an active zone** in the target Cloudflare account (so the
   `beta.do.zone` custom-domain DNS record can be created).
2. **Create a Cloudflare API token** with:
   - Account → *Workers Scripts*: Edit
   - Zone (`do.zone`) → *Workers Routes*: Edit
   - Zone (`do.zone`) → *DNS*: Edit
   - Account → *Account Settings*: Read
3. **Add repository secrets** (Settings → Secrets and variables → Actions):
   - `CLOUDFLARE_API_TOKEN`
   - `CLOUDFLARE_ACCOUNT_ID`
4. The **first deploy** should be triggered/verified by the owner (via a push to
   `main` or the workflow's "Run workflow" button).

### Local deploy (optional)

```bash
./gradlew clean build-style jsBrowserDistribution
CLOUDFLARE_API_TOKEN=... CLOUDFLARE_ACCOUNT_ID=... npx wrangler deploy
```
```
